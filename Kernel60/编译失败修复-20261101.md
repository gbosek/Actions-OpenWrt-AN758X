# 41221413413 工具链失败修复

准确失败提交23a6fa9，运行41221413413，job124596575874，Handle toolchain阶段。tools/install成功后，toolchain/kernel-headers将通用补丁应用到官方Linux6.18.60，782-v7.3-USB-serial-option-add-Quectel-EG060W.patch两个hunk失败。整机内核/固件尚未开始编译。

官方6.18.56已原生包含该USB串口模组支持，稳定提交8b495843267b93bc1b395d51f929bcb1f97f84ba（上游cd243401994880b8b6810c53177bce56eebaece5）。本次删除重复782回移补丁，保留6.18.60原生定义和设备ID，不引入USB模块到XG2010G成品。

本地第一次637补丁检查存在方法错误：`patch --batch`遇到已应用的补丁会自动反向应用并返回成功。旧final-patch-replay.log明确记录了“Reversed ... Assuming -R”，因此此前“637个补丁全部验证通过”的说法不能证明正向应用，也把原生EG060W代码反向删除了。此结论已撤回；原始日志保留，供审查。不能把这次失败归因于网络、PPE、NPU内存修复或USB硬件故障。

修复后的验证：

- 使用同一个强制正向、fuzz=0的执行函数；已原生包含的补丁必须失败，禁止自动反向或跳过。
- 以负向用例证明重复原生补丁被拒绝且源码不变。
- 从官方归档分别重放工具链用的454个通用补丁和目标固件用的636个完整补丁；核对原生USB定义/ID仍各一处、全部关键PPE/NPU/流表/LED源码哈希一致。
- 额外执行ARM64 UAPI headers_install，覆盖上次失败阶段的后续实际操作。
- 迁移安装器验证重复文件的精确删除；重跑安装、幂等和未知改动拒绝用例。没有降低源码哈希或放宽版本检查。
- 在CI工具链编译前加入两套补丁队列检查；工具链缓存标识纳入内核版本及通用补丁/头文件。

XG2010G范围：配置和旧成品manifest均不包含外接USB/串口模组/USB存储/WiFi组件；成品检查新增拒绝USB模组、蓝牙和音频等无用包。USB SerDes复用给以太网PCS，PHY_AIROHA_USB与usb_pcs仍保留。用户要求的PON、双WAN、PPE/NPU、MWAN4、NPU内存r914和500–1400MHz方案均保留。
