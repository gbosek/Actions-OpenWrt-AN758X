# XG2010G 1456 PPE 修补候选构建

分支基于 `3d009733635105521c253a0e8b48b50f21840615`，对应“github生成固件”最新要求和修复。PonWrt 固定为 `a57faf93c6c3638ba3651690228aabaa51d3f235`。

沿用最新两份超频固件的插件和默认配置：naoki / luanmuc 两个 NPU LuCI 版本、各自 ONU/PON 插件组合、MWAN4 停止反馈和原生启动规则、RPS 正常读取与单实例守护、四核使用率、CPU/PON/LAN1/LAN2 温度、铺满的 PON 卡片、WOL 中文界面、Argon 中文配置和 Bing 登录壁纸、概览卡片独立加载、默认 LAN `192.168.10.1` 以及 `500–1400MHz` 动态兼容超频。保留配置升级的网络设置仍按基线逻辑处理。

新增内核候选按顺序安装：

1. 保留发布 931 v2：NPU 统计拒绝时继续初始化 PPE。
2. 932：移除 SRAM flush 的内层 `err` 遮蔽，使失败返回初始化调用者。
3. 933：保留 TC 的 IB1 模板；仅在硬件仍 BND、packet type 相同时同步 BND 时间戳。

普通 FOE 提交继续使用 FE MMIO。两份 NPU LuCI 不代表两个 RV32 固件版本；构建检查要求 1456 code/data 的 SHA256 与现有基线一致。

933 是局部实验候选：现有 hash 解除时序不变。ACK 超时恢复、失败失效后的对象保留/重试、锁与 RCU、旧 PPPoE SID 清理和同五元组入口隔离尚未由此修复。原厂 5.4 / 6.6 的主机 HWNAT 反编译用于确认控制语义，未移植原厂模块或替换 RV32 固件。

本轮 CI 在完整编译前 prepare 实际内核，并提取实际 update/flush 函数体执行 16 项主机夹具。覆盖 UNB/非 BND 不污染模板、匹配 BND 只更新时间戳、packet type 不同、hash 不匹配、无关联、读表无结果、L2 分支，以及 flush 首项/中项失败返回和终止。夹具边界替代锁、表访问和 ACK，不代表设备运行验证。

编译后继续执行基线插件/PON/超频检查，检查实际驱动对象、FLOW_STATS=y 和 staged rootfs 中的 1456 文件 SHA，结果保存为 `PPE-BUILD-VERIFICATION.json`。只有检查通过才上传固件。预发布 tag 包含 NPU LuCI 版本与构建提交，保留现有发布和工作流记录。
