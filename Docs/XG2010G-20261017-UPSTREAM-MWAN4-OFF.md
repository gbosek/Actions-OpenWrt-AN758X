## OpenWrt 059895c

932 原先通过移除被遮蔽的局部变量恢复错误传播；本次替换为上游 d7d81b0 的原始补丁，提交 SRAM 失败时立即返回错误。931 NPU 统计拒绝回退和 933 TC 模板候选修复继续保留。

其余有用修复复用已经存在的实现，具体映射见 UPSTREAM-059895-SOURCE.json：934 TRTCM 重试及回读、923-01 共享 TX 队列 BQL、923-02 skb 分片 DMA、920-13/920-16 最大接收长度及 PPE MTU/L2 开销、170 无损 MIB，以及 915-02 flowtable QoS/DSCP。保留 PON 适配版本，不重复添加 OpenWrt 的 188/189/190/192。看门狗及 RX31 修复由 Linux 6.18.55 原生提供，不重复加入 935/936。未增加组播更新、可选新 LRO 功能或整组 Airoha 补丁重定基。

构建准备后和编译后均检查实际驱动源码，生成 UPSTREAM-059895-VERIFICATION.json；原有 ARM64 对象、NPU 固件身份、PPE 函数和安装后 rootfs 检查继续执行。

## MWAN4

- 后端本地版本 r8 在 r7 的基础上加入默认停止策略；LuCI 本地版本 r12 基于既有 r11 启停确认修复。
- 新固件首次启动（包括保留配置升级）停止 MWAN4 并关闭自启动。保留原有线路和策略；此后手动启动可恢复自启动，普通重启会沿用用户选择。
- LuCI 的“启动”同时 enable/start，“停止”同时 disable/stop，与 mwan4 CLI 行为一致。接口运行控制要求先启动整个服务。
- 开机回调检查是否启用，自定义 reload 只重载正在运行的服务。热插拔通过实际 procd 进程及停止标记判断运行状态，旧状态目录不会让停用服务恢复规则。
- RPC 使用只读初始化，避免状态页面创建运行目录。刷新按钮只读取状态，不再重启服务。
- 停止时仍可编辑配置，应用后保持停止。运行中应用可以重启，但应用期间被停止的服务保持停止。
- 原首次开机双 WAN 预设移为显式启动时运行的 helper；只有未修改的 stock 模板才应用，既有用户配置保持原样。

本地验证使用完整 Linux 6.18.55 补丁队列、实际 PPE/TRTCM 函数、真实修改后的 shell/ucode/JS 函数及隔离命令桩。固件完整编译、对象检查和真实主题布局检查由 GitHub Actions 执行。未对路由器刷机或进行硬件稳定性验证。
