# XG2010G 下一版修复与构建（2026-10-14）

本次实际编译范围：gbosek/Actions-OpenWrt-AN758X，两份超频固件（naoki / luanmuc NPU LuCI），仅Gemtek XG2010G。动态ondemand500–1400MHz，PPE net v2补丁、原生四核CPU使用率及CPU/PON/LAN1/LAN2温度保留。

## 已修复

- MWAN4停止/启动后立即读取真实procd服务状态，状态符合请求才提示成功；错误或未确认请求显示失败；停止时显示“已停止”，旧轮询不能覆盖新状态。
- PON概览卡片铺满内容区域，显示名称PON，实际采样接口pon0不变；桌面和手机均不横向溢出。
- 概览先返回页面框架，各卡片独立更新，不再等待最慢的卡片与网络缓存刷新。每卡片最多一个在途请求，慢查询不堆积，失败后独立重试；收起/展开及一次性初始化保留。PON首次无历史速率样本时不再强制等待500毫秒，下轮使用真实采样差。
- 加入luci-app-argon-config及中文包，沿用仓库Argon 2.4.7主题及默认Bing每日登录壁纸；可在主题配置中上传多张本地背景随机展示。壁纸地址查询失败时主题回退自带背景；保留升级时以用户已有主题配置为准。
- RPS守护使用cat读取内核参数，不以read返回值清空已读取数据；flock与固定procd实例避免重复watcher，继续尊重packet_steering关闭选项。
- MWAN4启动直接使用原生规则/路由生成函数，按实际UCI顺序、mask与接口生成；只要所选家族中IPv4已在线，IPv6等待阶段不阻塞整个接口初始化。运行时hotplug子进程保留固定PATH和绝对shell路径。
- 全新且未修改的MWAN4模板按实际存在的wan/wanb启用，使用本地可配置探测目标；默认0/未设置的metric分配10/20，保留非零自定义值。识别实际wan6或自动wan_6接口。已保留的自定义MWAN4配置、拨号凭据、物理端口和DNS不覆盖。
- 加入标准luci-app-wol、中文包与etherwake；新建LAN配置默认192.168.10.1，保留配置升级时仍以已有LAN设置为准。
- naoki使用指定的naoki66/OpenWrt_ONU_CONFIG，同时保留此次修好的PON状态卡片；luanmuc维持原PON配套。naoki NPU LuCI已核对仍为上游最新提交323539c。

已读取用户分享的94l6KwiIKbBvKhoTTs1VKq会话。RPS误报有记录中的具体读数支持，已修复并验证。记录仅凭版本号称R5“旧版env-i BUG”不能作为完整根因证据：R5/R7主路由代码相同，接口编号包含禁用段是既定映射，现场脚本固定table1/2才会错配。当前原生初始化用真实编号，不打入现场硬编码DNS/路由兜底脚本。
