# 040G-MD 教程与 XG2010G 当前方案

用户说明截图来自相同 CPU 的 Nokia XG-040G-MD。PBS05 的机型支持表也将 XG-040G-MD 与 XG2010G 列为 AN7581：https://github.com/pbs05/uboot-an758x 。这证明 SoC 相同，不能证明两块板的供电、散热、芯片体质或正在使用的 BL31/ATF 接口一致。当前没有截图对应的源码/ATF 版本，不能把说明文本当已审阅的实现。

2026-11-01 通过固定 SSH 身份只读检查 XG2010G：boost_backend=kernel-pll，boost_capable=1，ondemand，策略下限 500MHz、上限 1400MHz；普通频率表 500–1200MHz/50MHz 步长，1400MHz 为 boost 档。采样时实际频率会变化，不能将两次不同时间的读数相减判断误差。

| 教程设计 | 当前实现与本次处理 |
|---|---|
| 按负载动态调频 | 已有 cpufreq/ondemand，不是固定满频，保留 |
| 从 PLL 读真实频率 | 已有整数 PCW/POSDIV 回读及有效性检查；切到临时时钟期间报告上次完成的 OPP 并暴露 transitioning，不把临时值冒充稳定值，保留 |
| 开机恢复策略、避免反复写引导环境 | 已有 cpufreq 启动一次应用与显式 UCI reload，保留；没有引入每秒写 UCI/环境或常驻调频脚本 |
| 所有频率都经专用 ATF 接口 | 当前普通档走原 BL31，1200↔1400 由内核兼容 helper 完成。缺少该教程 ATF 的公开 ABI 和 XG2010G 适配证据，本次不猜测调用 |
| 高频段细分与更高上限 | 仅凭同 SoC 不能确定稳定性；不新增 25MHz 高频档或提高 1400MHz 上限 |
| 固定频率以及超温警告 | 不能把固定频率当温控保护；保留动态默认值。现有失败回滚不等于挂死后一定能恢复，也不等于已验证热/电气稳定 |

有帮助的原则已经在当前方案实现。本次增加对“普通档仍走 SMC、实际 PLL 读取、转换中状态和原策略所有者”的成品源码检查，防止内核迁移遗漏，而不引入未经核实的高频/ATF 改动。

本次未改变在线 CPU 策略、PLL、电压、ATF、U-Boot 或 NPU 时钟，也未执行负载测试。提高 CPU 频率不会直接增加 NPU 核心、PPE 准入条件或硬件表容量；实际收益需要在相同业务与温度条件下验证。
