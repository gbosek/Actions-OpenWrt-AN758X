# Gemtek XG2010G / AN7581 代码审查与修复

日期：2026-10-06。目标分支：`multiwan-ppe-experimental`。

## 基线与范围

以 GitHub #24 的真实 ITB、仓库集成代码，以及 PonWrt 固定提交
`c3b518baec8ed0cc5a353327fa154f38bde1e6c0` 的实际准备/编译源码交叉检查。
重点覆盖动态 WAN1、驱动出口与 MTU、热插拔恢复、CPU 调频/显示、PON 遥测、包索引和 CI。
这项审查不等于逐行证明整个 Linux 内核或闭源 NPU 固件没有缺陷。

硬件是 Gemtek XG2010G，CPU 为 AN7581，无 Wi-Fi。保留 Linux 6.18.52、R68 PON、
1456.62 NPU，以及 powersave 启动保护、默认最高 1400 MHz 的 CPUfix；1600 MHz 仍是
可选且未实机验证的上限。本次构建的四份 CPU DTS/调频源文件哈希未变，实际 FIT
设备树也与前一份 CPUfix 审查镜像逐字节一致。

## 发现和处理

| 位置 | 问题 | 修复 |
|---|---|---|
| WAN1 自动选择 | 访客区 masquerade 可能被误认作 WAN；IPv6/@别名先占候选 | 使用 WAN 区/显式选择，先排序再按物理口去重，有限递归解析 VLAN/别名 |
| LAN/WAN VLAN | `lan3.10` 与 `lan3.20` 共享物理口时，旧桥检查可能漏掉 LAN 成员 | UCI 桥端口和运行时 brport 都解析物理父口，避免整口错误改为 WAN1 |
| 角色切换 | 同一物理口有多个逻辑接口时恢复不完整；失败触发热插拔循环 | 保存全部活动/待连接使用者及管理状态，检查 down/readback，恢复接口，增加 30 秒失败冷却 |
| 并发 | mkdir 锁可能留下后阻止处理；配置读取错误可能改变角色 | 使用有界 flock；读取失败保留现有角色；ifdown 和 UCI reload 后重新核对 |
| WAN1 MTU | 逻辑 LAN 的动态 WAN1 没有设置 WAN1 FE MTU 字段 | 939 使用已有 `REG_WAN_MTU0` 内 `WAN_MTU1_MASK`，保持 WAN0 字段独立 |
| Packet steering | 普通“启用”模式被板级 helper 清零 | 模式 1 保留 netifd RPS，模式 2 使用四核掩码，模式 0 清零；修正状态返回 |
| 手动诊断 | 文本匹配 UP 可把 LOWER_UP 误当管理 UP | 检查 sysfs flags 的 IFF_UP 位 |
| PON 卡片 | 无效数字显示成零；共享统计来源缓存阻止失败恢复 | 按设备缓存、恢复探测、过滤无效值/重复设备；连接数标记为整机统计 |
| 概览温度 | 系统卡片重复查询 PON、分散遥测归属 | 系统温度只读 CPU/热区，光模块由 `15_pon` 卡片查询 |
| CPU 使用率 | 整数除法令低负载显示零 | 两次 `/proc/stat` 浮点采样，保留 0.1%；包含 steal、不重复 guest，异常显示 `?` |
| 包索引 | PON 在索引后覆盖；索引失败被 `|| true` 掩盖 | 本地 PON 卡片先复制再索引，失败终止；清理重复来源 |
| 依赖一致性 | 索引/config/manifest 分别维护包清单，容易漂移 | `configs/xg2010g-required-packages.txt` 与共享检查脚本统一 58 个必要包 |
| 构建确定性 | NAT 页面来源浮动；旧 patch hunk 行数不准确 | 固定 NAT 提交，修正 929/930 行数，检查全部 15 个自有补丁 |
| NOWIFI | XG2010G 仍被通用流程加入无线配置 | 单机型流程跳过无线默认值，其他机型保留通用逻辑 |
| overlay/时区 | 重跑时 files 目录可能嵌套；时区有多处不一致修改 | 复制 overlay 内容；统一使用时区 defaults，检查 UCI/reload 错误 |

NAT 固定提交 `2609164ff608ee4e6ac7e63fd5896176805bd9ed` 的 CLI 脚本与此前源码
SHA256 相同，本次没有改变 NAT 模式规则。

## GDM2 / LAN 改 WAN

938 已存在于 #24，回移 Linux 上游
[8e0a754b0836d996802713bbebc87bc1cc17925c](https://github.com/torvalds/linux/commit/8e0a754b0836d996802713bbebc87bc1cc17925c)。
它让存在真实 GDM2 的设备，对其他 GDM 物理端口使用直接 FOE 出口。
XG2010G 的 GDM2 承担 PON；当前 LAN3 位于 GDM4。动态 WAN1 保持直接路径，不启用
GDM2 回环、不切换整个 GDM 的 QDMA 角色。GDM4 的原始物理 PSE 出口编号是 9。

错误回环可能造成额外转发和共享队列压力，不能仅凭旧丢包累计值确定原因。
本次同时保留 938 并编译 939 WAN1 MTU 修复；没有以 SQM 或禁用 NPU 代替驱动修复。

当前驱动仍只有一个外部硬件 WAN1 槽。自动选择不固定 LAN3/wanb，但两个外部 WAN
同时存在时必须显式选择一个。物理端口的硬件角色覆盖整口，因此不能声称同一口的
LAN VLAN 与 WAN VLAN 能独立切角色；这种配置会被 helper 拒绝自动提升。

PSE6/NBQ5/6 可以是 NPU 统计路径，不能直接当物理出口。验收要针对真实双向流连续
采集 `HW_OFFLOAD`、FOE BND、PPE/QDMA 和实际出口计数。低 CPU、测速快或统计图
不能单独证明硬件卸载。

## 插件

先前推荐加入的四类诊断/维护插件均已编译：

| 插件 | 用途 | 默认边界 |
|---|---|---|
| [vnStat2](https://github.com/vergoh/vnstat) | 接口日/月流量历史 | 新装时从 PPE 驱动发现物理 Ethernet 接口；每小时保存至 `/etc/vnstat2/`，升级保留；断电可能损失最近一小时 |
| [LuCI Statistics](https://github.com/openwrt/luci/tree/master/applications/luci-app-statistics) | 每核 CPU、频率、温度、内存历史 | 每 30 秒采样；RRD 存 RAM，重启丢失；Wi-Fi 采集关闭 |
| [MTR](https://github.com/traviscross/mtr/blob/v0.95/man/mtr.8.in) | 每条线路逐跳延迟和丢包 | 使用 JSON 版本；中间跳的 ICMP 限速不等于终点业务丢包 |
| [WireGuard](https://github.com/openwrt/luci/tree/master/protocols/luci-proto-wireguard) | 远程维护 | 提供界面/工具，尚未建立隧道；不承诺 VPN 加密流量走 PPE |

对于最后讨论的 WOL、Watchcat、SQM、Turbo ACC，用户选择**只加入 WOL**：
`luci-app-wol`、中文包和 `etherwake`。入口为 **服务 → 网络唤醒**，默认没有开启
开机自动唤醒示例目标。电脑网卡、BIOS 和当前电源状态还需支持 WOL。

Watchcat 可重启接口或整机，但本次没有加入自动恢复服务；双 WAN 故障切换继续由
mwan3 管理。[SQM 官方说明](https://openwrt.org/docs/guide-user/network/traffic-shaping/sqm)
指出硬件 flow offload 会绕过软件整形，本次不启用。
检查的 [Lean Turbo ACC](https://github.com/coolsnowwolf/luci/tree/master/applications/luci-app-turboacc)
依赖旧 iptables offload/SFE，硬件入口针对 MT762x/Filogic，不能解决 AN7581 的 WAN1/GDM2 问题。

物理 Airoha `.ndo_get_stats64` 读取硬件 MIB，比 br-lan/PPPoE 软件计数更适合观察
PPE 流量；仍需实测准确性。vnStat 按口统计，不能把 LAN、WAN 同一业务在不同口
的字节相加当“总上网流量”。Statistics 默认接口图仍为 br-lan，可在界面选择
物理口；仅用于趋势。mwan3 的 `0x3f00` 与 PBR 默认 `0x00ff0000` 掩码不同，
不能断言两个包默认直接冲突；PBR 默认未启用，本次未新增分流规则。
